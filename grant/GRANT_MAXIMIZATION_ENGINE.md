# Grant Maximization Engine

## Purpose

Translate the verified project scope into the strongest defensible funding request for a specific grant program without inflating claims or costs.

## Funding maximum rule

Before setting a requested amount, verify from current official program sources:

1. Eligibility.
2. Funding range and maximum.
3. Allowable costs.
4. Review criteria.
5. Submission window and deadline.
6. Required application materials.
7. Any program-specific restrictions.

## Maximum Justifiable Ask

Define:

- **A — Minimum viable funding:** smallest amount that can deliver a credible project result.
- **B — Full project funding:** amount required to execute the defined scope, work packages, staffing, infrastructure, testing, and dissemination.
- **C — Program maximum:** current verified program ceiling.

The request should be:

`REQUEST = MIN(C, B)`

`B` must be derived from the actual work required. It must never be artificially increased merely to approach `C`.

## Budget defensibility

Every material budget line should map to:

`COST → TASK → DELIVERABLE → KPI → PROJECT IMPACT`

Decorative contingency, unsupported headcount, vague platform costs, and invented market assumptions are prohibited.

## Scenario budgets

Maintain at least three scenarios where useful:

- **FULL** — complete defined project scope.
- **REDUCED** — high-value scope with lower resource demand.
- **MVP** — minimum credible proof and validation package.

## Funding evidence rule

Program amounts and requirements are time-sensitive. A historical figure must never be reused as a current program limit without verification from the applicable official source.

## Grant red-team questions

- Is the requested amount mathematically defensible?
- Can each major cost be explained in one sentence?
- Does every KPI have a measurement method?
- Are targets clearly separated from achieved results?
- Are technical claims supported by evidence?
- Are program rules current?
- Could a reviewer reject any statement as exaggerated, vague, or unverifiable?
- Does the project remain credible under the REDUCED or MVP scenario?
